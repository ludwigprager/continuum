# Diagrams

Standalone, self-contained HTML for presenting the pipeline to management.
Each file embeds its own SVG, CSS and JS (no external requests) and opens
directly from disk — `file:///path/to/docs/diagrams/pipeline-architecture.html`
in any browser, no server and no network, which is what makes them safe to
carry into the air-gapped DC.

Each diagram exists in English and German (`*.de.html`), per SPEC §1: source
data is German, output labels support German and English. The diagram
content (titles, labels, cards) is authentically authored in each language;
only the viewer's own chrome (search, pan/zoom hints, theme toggle) stays
English in the German files — `archify`'s renderer only ships fixed UI
strings for `en`/`zh-CN` locales.

- `pipeline-architecture(.de).html` — the system end to end: git as system
  of record, the container pipeline, and the five report formats it produces.
- `import-lineage-dataflow(.de).html` — how overlapping legacy CSV extracts
  merge into the catalogue, with every conflict recorded and a manual
  inspection gate before anything becomes YAML.
- `daily-usage-workflow(.de).html` — what a team does by hand (edit YAML,
  open a merge request) versus what the pipeline does automatically after
  that.

These are illustrative, hand-authored snapshots, not generated by
`./report.sh` and not part of the report model (SPEC §5.2) — they describe
the pipeline itself, not the migration data it reports on. Regenerate them
with the `archify` skill if the architecture changes enough to make them
misleading.
